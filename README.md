# ФотоОтчёт — Android-приложение

Мобильное приложение для водителей и экспедиторов: съёмка груза с водяным знаком
и масштабированием камеры до ×5, история завершённых смен и отправка отчёта
пакетом фотографий в MAX через системное меню «Поделиться».

**Серверной части нет.** Ни бота, ни токенов, ни API MAX не требуется: фотографии
отправляются из приложения системным share-sheet, пользователь сам выбирает
приложение MAX и чат.

## Сборка

Требования: JDK 17, Android SDK (platform 36, build-tools 36.0.0).

### Рекомендуемый способ — скрипт

```powershell
cd android
.\build-apk.ps1
```

Скрипт создаёт junction с латинским именем (`%TEMP%\delivery-photo-link` на папку
проекта) и собирает через неё. Готовые APK копируются в `app/build/outputs/apk/`.

**Почему junction, а не просто сборка в текущей папке.** Каталог проекта лежит
в `D:\scorp\Cloude\Автоматизация работы Игорь\`, и путь содержит кириллицу.
Сама сборка в таком пути работает, но **тестовая JVM не может загрузить классы
из classpath с не-ASCII путём** — тесты падают с `ClassNotFoundException` на
собственном тестовом классе. Junction решает это без копирования исходников:
файлы те же, но все инструменты видят латинский путь.

### Варианты сборки

Сборка разделена по архитектуре процессора: телефоны — ARM, эмулятор — x86_64.
Разные варианты нужны и потому, что Gradle очищает каталог выхода при пересборке —
держать оба APK в одной папке нельзя, они затрут друг друга.

| Вариант | Команда | APK | Размер | Куда ставить |
|---|---|---|---|---|
| Телефон, release | `.\build-apk.ps1 -Task ":app:assembleArmRelease"` | `arm/release/app-arm-release.apk` | 29,3 МБ | водителям |
| Телефон, debug | `.\build-apk.ps1 -Task ":app:assembleArmDebug"` | `arm/debug/app-arm-debug.apk` | 46,2 МБ | отладка на телефоне |
| Эмулятор | `.\build-apk.ps1 -Task ":app:assembleX86Debug"` | `x86/debug/app-x86-debug.apk` | 38,0 МБ | эмулятор |

У варианта для эмулятора отдельный `applicationId` (`ru.delivery.photo.x86.debug`),
поэтому его можно поставить рядом с обычным приложением, не вытесняя его.

Тесты: `.\build-apk.ps1 -Task ":app:testArmDebugUnitTest"`.

## Как это работает

```
1. Рейс                 → только состав экипажа (ФИО + автомобиль)
2. Точка разгрузки      → выпадающий список: выбрать, переименовать, удалить
3. Съёмка               → тип кадра (Объект / Этикетка), зум кнопками или щипком до ×5
4. Подтверждение        → проверка штампа и серийного номера
5. Отправка             → share-sheet: выбираем MAX и чат
6. Завершение смены     → кнопка «Завершить» переносит рейс в «Историю рейсов»
```

Нижнее меню — три вкладки: **Съёмка**, **Фото** и **История**. Поля «Рейс» для
ручного ввода нет: номер создаётся автоматически по московскому времени начала
смены, например `12.11.2026 14:32`. Он попадает в водяной знак и служит
названием записи в истории.

Подписания документов больше нет: ни окна после отправки, ни вкладки, ни
напоминаний. Старая задача WorkManager отменяется при обновлении приложения.

**Экипаж рейса.** В рейсе может быть несколько водителей с разными машинами.
На экране «Съёмка» водитель переключается между ними чипами; в водяной знак
попадают ФИО и автомобиль выбранного. Состав задаётся в диалоге рейса
(«Изменить» в шапке).

**Точки разгрузки.** Список — на вкладке «Съёмка». У каждой точки есть
карандаш (переименовать) и корзина (удалить вместе с фотографиями). На
вкладке «Фото» показывается только галерея выбранной точки.

**Просмотр фото.** Тап по миниатюре открывает снимок во весь экран — на вкладках
«Съёмка», «Фото» и в истории рейса. На активной съёмке фото можно удалить;
в истории — только смотреть, чтобы архив не менялся случайно.

**Зум камеры.** Кнопки `−` / `+` в правом верхнем углу превью и жест «щипок»
меняют кратность от 1 до ×5. Верхнюю границу дополнительно ограничивает
диапазон, который сообщает сама камера: если физический зум меньше, ×5 не
будет доступен.

**История рейсов.** Кнопка «Завершить» в шапке экрана «Съёмка» закрывает смену:
рейс, экипаж, точки и фотографии переходят в историю, а съёмка продолжается уже
в новом рейсе. Запись истории показывает период смены, водителей и автомобили,
список точек разгрузки, все снимки по точкам и количество отправок. Кнопка
«Отчёт по рейсу» собирает **все фото рейса** одним пакетом с подписью (водители,
точки, серийные номера, время) и открывает тот же share-sheet, что и отправка
по точке. Кнопка «Заново» повторяет отправку уже помеченных фотографий.

### Водяной знак

Наносится **на устройстве, до отправки в сеть** — сырой кадр без маркировки
никуда не уходит. Дважды:

- **в пиксели** — видно человеку, переживает пересжатие в мессенджере;
- **в EXIF** — машиночитаемо: GPS, дата/время, описание кадра, ПО.

Оформление повторяет принятое в компании: правый нижний угол, белый текст с
чёрной обводкой, запятая как разделитель дробной части, русская дата по ГОСТ.

```
ООО Интех
55,75387, 37,62363
12 нояб. 2026 г. 13:30:33
Рейс 12.11.2026 14:32 · Точка разгрузки 1
SN: 26100347
```

Особенности:

- **Организация** (первая строка) настраивается в «Фото» → шестерёнка.
- **Точность GPS** выводится только когда она плохая (> 30 м) — «точные координаты»
  без указания погрешности вводят в заблуждение. В EXIF точность пишется всегда.
- **Первая строка шапки** (рейс, точка, серийник) дублируется на **каждом** снимке
  намеренно: при отправке через share-sheet поле `EXTRA_TEXT` получатель может
  проигнорировать, а так подпись гарантированно доживёт внутри картинки.
- Время — всегда московское (UTC+3), независимо от часового пояса устройства.

### Серийный номер

Извлекается только с кадров типа «Этикетка», в три ступени:

1. штрихкод / QR / DataMatrix (ML Kit Barcode);
2. OCR + разбор по шаблонам этикетки;
3. ручной ввод.

**Распознанный номер никогда не подставляется в водяной знак без подтверждения
человеком.** Ошибка OCR в штампе выглядит как достоверный серийник — это хуже,
чем пустое поле. Исходный распознанный текст сохраняется в базе для разбора
спорных случаев.

Под шильдики дизель-генераторов (EAC) настроен разбор поля `NO.`:

```
DIESEL GENERATING SETS EAC
TYPE DCS-265KVA   NO. 26100347
P 212 kW 265 kVA 400 V 382.5 A
```

`26100347` — серийный номер. Разбор учитывает приоритет якорей (`NO.` → `SN`/
`Serial` → `Part`), требует, чтобы якорь был отдельным словом (иначе `no`
цепляется к `KNOB`), и отбрасывает кандидатов без цифр.

**Языки распознавания.** Шильдики англоязычные, поэтому основной распознаватель —
латинский; русский используется как запасной (на части этикеток есть кириллица).

**Подсказка при съёмке.** В режиме «Этикетка» на экране камеры рисуется рамка:
шильдик занимает на кадре небольшую долю, а фон (небо, асфальт) мешает OCR.
Для распознавания берётся только центральная область кадра (92 % × 62 %),
соответствующая рамке. В сохранённый снимок при этом попадает **весь кадр** —
усечение применяется только к распознаванию.

### Отправка

`Intent.ACTION_SEND_MULTIPLE` + `FileProvider` → системное меню «Поделиться».
Пользователь сам выбирает приложение (MAX) и чат.

Три стратегии (переключаются в «Фото» → иконка шестерёнки):

| Стратегия | Поведение |
|---|---|
| Альбом (по умолчанию) | все фото одним сообщением |
| Частями | порциями по N фото, в подписи «часть K из M» |
| Коллаж | одно изображение-сетка со всеми кадрами |

**Стратегию нужно проверить на реальном устройстве в MAX:** собирает ли получатель
несколько файлов в одно сообщение-альбом или режет на отдельные сообщения. От
этого зависит выбор значения по умолчанию.

### Отчёт по рейсу

Отчёт — это не CSV, а тот же пакет фотографий через share-sheet. Разницы для
пользователя нет: отчёт по точке и отчёт по всему рейсу отправляются одинаково,
меняется только подпись и набор снимков. В истории можно отправить отчёт по всему
рейсу сразу или повторить отправку уже помеченных фотографий.

## Устройство проекта

```
android/app/src/main/java/ru/delivery/photo/
├── MainActivity.kt              Точка входа
├── DeliveryPhotoApp.kt          Application: БД, хранилище
├── domain/                      Модели, форматирование времени, разбор серийников
├── data/
│   ├── db/                      Room: рейсы, точки, экипаж, фото, пакеты
│   ├── DeliveryRepository.kt    Единая точка доступа к данным
│   └── PhotoStore.kt            Файлы фотографий во внутреннем хранилище
├── watermark/
│   └── WatermarkRenderer.kt     Наложение штампа + запись EXIF
├── location/LocationProvider.kt GPS через LocationManager (без Google-сервисов)
├── serial/SerialExtractor.kt    Штрихкод и OCR на устройстве
├── camera/CameraController.kt   CameraX, зум до ×5
├── share/                       share-sheet, подписи, коллаж
└── ui/                          Compose-экраны: съёмка, фото, история
```

### Важные технические решения

- **Без Google Play Services.** В российских сборках Android их нет, поэтому
  геолокация — через `LocationManager`, а ML Kit используется в варианте *bundled*
  (модели внутри APK).
- **Файлы — во внутреннем хранилище.** Служебные кадры не попадают в общую галерею
  устройства; наружу отдаются только через `FileProvider` и явное действие пользователя.
- **Разрешение — до 3000 px, JPEG q90.** Достаточно для мессенджера, при этом
  файлы в разы легче полноразмерных кадров камеры.
- **Всё локально.** Нет сети — приложение работает полностью; отправка идёт
  явным действием пользователя.

## Что изменилось после первого теста на устройстве

| Проблема | Причина | Исправление |
|---|---|---|
| Вылет при нажатии «Выберите точку разгрузки» | выпадающий список на `ExposedDropdownMenuBox` требует якорь с `menuAnchor()` и без него падает | список переписан на `DropdownMenu` — без этого требования; добавлены переименование и удаление точки |
| После перезапуска приложения рейс виден, а фото снять нельзя | выбранная точка разгрузки жила только в памяти ViewModel и терялась при перезапуске | идентификатор точки хранится в базе и восстанавливается при старте |
| «Ошибка обработки снимка: It's prohibited to register multiple handlers…» | в `LocationProvider` на одну корутину регистрировались **два** обработчика отмены — kotlinx.coroutines разрешает только один | обработчик отмены объединён в один |
| Снимок повёрнут на 90° | часть устройств пишет JPEG с EXIF-тегом ориентации, который не все просмотрщики учитывают | ориентация применяется к пикселям сразу после съёмки, тег сбрасывается |
| Подписание документов | функционал не нужен по новой задаче | удалено полностью: БД-миграция 2→3, классы и уведомления удалены, старая задача WorkManager отменяется при запуске |
| Режим камеры «Погрузка» | не нужен | удалён; старые снимки при чтении считаются объектами |
| Ввод номера рейса | пользователю не нужен | номер создаётся автоматически из московского времени начала смены |
| Лишний тип фото «Повреждение» | не требуется | удалён |
| Несколько водителей и машин в рейсе | требовалось | добавлен состав экипажа с переключением на экране «Съёмка» |
| Нет истории смен | нельзя повторно отправить отчёт по рейсу | добавлена вкладка «История», кнопка «Завершить» и отчёт по всему рейсу |
| Нет приближения камеры | мелкий шильдик плохо читается | добавлены кнопки зума и жест «щипок» до ×5 |

Координаты при съёмке берутся из системы автоматически. На экране камеры
показывается индикатор текущих координат и точности GPS — водитель видит,
что геометка пишется.

## Запуск в эмуляторе

На машине установлены Android SDK и образ `system-images;android-36;default;x86_64`
(без Google-сервисов — приложение они и не использует). Аппаратное ускорение
доступно через WHPX, система поднимается за ~50 секунд.

```powershell
cd android
.\run-emulator.ps1
```

Скрипт поднимает AVD `PhotoReport`, ставит APK, задаёт координаты и открывает
приложение.

**Архитектура APK.** Эмулятор всегда x86_64, поэтому для него есть отдельный
вариант сборки — см. таблицу в разделе «Сборка». Скрипт `run-emulator.ps1`
ставит его сам.

Полезно вручную:

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"

& $adb emu geo fix 37.62363 55.75387        # долгота, затем широта!
& $adb shell pm grant ru.delivery.photo.x86.debug android.permission.ACCESS_FINE_LOCATION
& $adb logcat | Select-String "delivery.photo"
```

⚠️ `adb emu geo fix` принимает **долготу первой**, затем широту — порядок
обратный привычному. Для Москвы: `geo fix 37.62363 55.75387`.

У варианта для эмулятора свой пакет `ru.delivery.photo.x86.debug`, поэтому
в `adb shell am start` нужен полный адрес:

```powershell
& $adb shell am start -n ru.delivery.photo.x86.debug/ru.delivery.photo.MainActivity
```

Приложение берёт координаты из системы, поэтому в эмуляторе они задаются
через `adb emu geo fix` и попадают в водяной знак как на настоящем устройстве.
Камера эмулятора виртуальная: превью и съёмка работают, изображение —
синтетическая сцена.

Тонкость: эмулятор и AVD хранятся в `C:\Users\<user>\.android\avd`,
то есть в латинском пути — иначе Gradle и сам эмулятор снова упрутся
в кириллицу (см. раздел «Замечания по сборке»).

## Оформление

Интерфейс сделан в духе iOS: системные цвета Apple, крупные заголовки,
скруглённые группы на «сгруппированном» фоне, сегментированные переключатели
вместо чипов, тумблеры вместо чекбоксов.

Три режима оформления — **как в системе / светлая / тёмная** — переключаются
в «Фото» → иконка шестерёнки → «Оформление». Выбор сохраняется.

Используются системные цвета:

| | Светлая | Тёмная |
|---|---|---|
| Фон | `#F2F2F7` | `#000000` |
| Карточки | `#FFFFFF` | `#1C1C1E` |
| Акцент | `#007AFF` | `#0A84FF` |
| Разделители | `#C6C6C8` | `#48484A` |

Шрифт — системный sans-serif: SF Pro на Android недоступен, поэтому взяты
метрики и интервалы iOS при шрифте устройства.

## Распространение (MDM нет)

Готовые APK лежат в `app/build/outputs/apk/`:

| Сборка | Размер | Назначение |
|---|---|---|
| `arm/debug/app-arm-debug.apk` | 46,3 МБ | отладка на телефоне, `applicationId` с суффиксом `.arm.debug` |
| `arm/release/app-arm-release.apk` | 29,3 МБ | пилот водителям: R8, ресурсы урезаны |
| `x86/debug/app-x86-debug.apk` | 38,2 МБ | эмулятор, `applicationId` `ru.delivery.photo.x86.debug` |

Release-сборка подписана **отладочным ключом** — этого достаточно, чтобы APK
ставить на устройства без MDM. Для публикации в RuStore нужен собственный
ключ:

```powershell
keytool -genkey -v -keystore delivery.keystore -alias delivery -keyalg RSA -keysize 2048 -validity 10000
```

и соответствующая запись в `signingConfigs` в `app/build.gradle.kts`.

| Вариант | Плюсы | Минусы |
|---|---|---|
| **RuStore** | бесплатный хостинг APK вместо своего сервера, автообновления | аккаунт разработчика + модерация 1–3 недели |
| Раздача APK через корпоративный чат MAX | ноль инфраструктуры, работает сразу | ручная установка из «неизвестных источников», обновления вручную |

Рекомендация: для пилота — раздача через чат, затем перевод в RuStore.

**Размер APK.** Основной вес — нативные библиотеки ML Kit (~40 МБ на две
архитектуры). x86 и x86_64 исключены через `abiFilters`: на телефонах они
не используются, а добавляли бы ~34 МБ.

---

## Что осталось доделать

1. **Проверить поведение MAX на `ACTION_SEND_MULTIPLE`** (альбом или отдельные
   сообщения) и выбрать стратегию по умолчанию. Самая дешёвая и самая важная проверка.
2. **Проверить качество распознавания на реальных шильдиках** — снять несколько
   кадров через приложение и посмотреть, предлагает ли оно `NO.` первым кандидатом.
   Если ML Kit плохо читает мелкий текст — увеличить область обрезки или добавить
   ручной ввод по умолчанию.
3. **Подобрать размер плашки штампа** под фактические листы снимков: съёмка с рук,
   яркое солнце, тёмная этикетка.
4. Убедиться, что штамп не перекрывает важную часть кадра (у генератора шильдик
   находится в верхней трети — перекрытия не будет).
5. Решить вопрос с часовым поясом, если для части рейсов нужен локальный.
6. Проверить потребность в `FLAG_SECURE` (запрет скриншотов).
7. Собрать APK для пилота на 2–3 водителях.

### Замечания по сборке

**1. Путь в `local.properties` — только с прямыми слэшами.**

```properties
sdk.dir=C:/Users/scorp/AppData/Local/Android/Sdk
```

Не `C:\Users\...`. Файл читается как Java Properties, и последовательность `\U`
в значении трактуется как escape-последовательность: путь превращается в
`C:UsersscorpAppDataLocalAndroidSdk`, становится относительным, и AGP падает с
невнятным `IOException` при поиске SDK. Это самая частая причина ошибки
«SDK location not found» на Windows.

**2. Кириллица в пути проекта.**

AGP отказывается работать с не-ASCII путями — отключается флагом
`android.overridePathCheck=true` в `gradle.properties`. Сборка APK в таком пути
работает, но тесты требуют латинского пути — см. раздел «Сборка».

**3. Сеть.** Загрузка Gradle и зависимостей идёт через `services.gradle.org`
и `dl.google.com`. При медленной сети увеличьте `networkTimeout` в
`gradle/wrapper/gradle-wrapper.properties` и/или запускайте сборку повторно —
артефакты докачиваются.

**4. Кодировка `.ps1`.** PowerShell 5.1 читает сценарии без BOM как ANSI —
кириллица в строках ломает разбор. Файл `build-apk.ps1` сохранён с BOM;
при правке вручную не забудьте его сохранить.

**5. ML Kit `text-recognition`.** В версии 16.0.1 нет `TextRecognition.getClient()`
без аргументов и нет `setLanguageTag`. Правильный вызов:

```kotlin
TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)
```

Латинская модель покрывает и кириллицу, поэтому отдельная русская модель
не нужна. `Text.getText()` возвращает строку сразу — `result.text`, без `result.text.text`.
